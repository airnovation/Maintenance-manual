# AI Voice Keyboard — Android prototype

**Status:** v0.10 experimental test build. Safe Undo and return-to-previous keyboard added; phone validation still required. Removes the standalone Pinyin keyboard in favor of the user's preferred Samsung/Gboard input method. Retains Mic and EN; both AI providers are instructed to produce concise, natural WhatsApp English. Changes require on-device validation. Code kept on `prototype/ai-voice-keyboard` branch of an existing Airnovation repository. This is a temporary location, not production infrastructure.

## What it does
1. Install the debug APK generated by the cloud build workflow.
2. Launch **AI Voice Keyboard**; give microphone permission.
3. Enable the input method in Android Settings; select it from the keyboard picker.
4. Open a WhatsApp, Gmail, or other app text input. Press **Mic** to start recording and **Stop** to finish (3-minute safety limit).
5. The recorded audio is sent to the selected API provider for transcription in the original spoken languages, including Chinese, English, and Malay; the transcript is then translated to English. A saved API key is required.
6. v0.7 automatically inserts successful voice-to-English translation into the focused chat draft, clearing the keyboard preview. Review the draft, then tap **Send** yourself. If insertion fails, a fallback **Insert** button appears.
7. For typed text, use the normal phone keyboard to type a WhatsApp draft. Switch to AI Voice Keyboard and tap **EN**; it replaces the unchanged draft with natural English but does not send it.
8. **Undo** restores the pre-translation chat draft only when the current draft exactly matches the just-translated result. Undo is canceled if someone has edited the text, to avoid wiping later typing. Undo history is RAM-only, lasts for the current field/session, and is cleared on keyboard exit or focus change.
9. **↩ Keyboard** switches directly to the previous Android keyboard on Android 9+ when supported; otherwise opens the keyboard picker. Backspace edits the host chat field, while Insert appears only if automatic insertion fails.

There is no automatic reading, sending, WhatsApp API integration, accessibility scraping, or background messaging.

## Cloud build (no PC required)
GitHub Actions workflow: `.github/workflows/build-ai-voice-keyboard.yml`.
The workflow runs on pushes to the prototype branch and produces the artifact `ai-voice-keyboard-debug-apk`, containing `app-debug.apk`. On Android, use GitHub web (desktop site if necessary) -> repository -> Actions -> completed successful workflow -> Artifacts -> download ZIP -> extract -> install APK. The in-app **Open GitHub Test Builds** button opens the Actions page; it is not an automatic version checker or background updater. On Android you may need to allow this browser/files app to install unknown apps. Only install if you trust the repository and build, and verify the workflow succeeded.

Android SDK 35, min SDK 26, Java 17, Android Gradle Plugin 8.9.2, Gradle 8.11.1. Debug builds use GitHub runner generated debug signing keys. Reinstallation/update across different cloud runners may require uninstalling the previous APK and losing app settings because debug key may change.

## AI setup and privacy
Your selected provider's API key is entered directly in the app Settings screen, encrypted using Android Keystore AES-GCM, and never committed to source control. No key is bundled in the APK. A **separate OpenAI API account with billing/credits** is required for OpenAI API translation and speech transcription; a ChatGPT subscription does not grant API usage. In v0.10, the app sends each completed voice recording to the selected provider for transcription, then sends the resulting preview text for translation. It does not read WhatsApp history. Requests specify `store: false` but OpenAI's applicable data handling terms still apply. Speech transcription now uses the selected Gemini or OpenAI API after the user presses Stop, not Android's speech recognition service. Temporary audio files are deleted after transcription finishes. Avoid use for sensitive, confidential, regulated, or protected information without a formal privacy/security review.

This is a **voice-first** input method, not a complete touch-typing keyboard. Switch to your normal keyboard via **Other Keyboard** for ordinary typing, passwords, or apps that do not accept this input method. AI English requires internet access. Speech recognition depends on your device's speech service and microphone permissions. Some app fields may not accept the insertion method.

## Prototype limitations
- No offline translation; no live streaming translation.
- Speech transcription supports Mandarin, English, and Malay in the prompt; mixed-language accuracy varies and depends on the selected provider.
- Password fields recognized by Android inputType disable voice, translation, and insertion; apps may classify sensitive fields inconsistently.
- User is responsible for reviewing AI output before inserting/sending.
- API errors keep original transcript; they do not send anything.
- Not security audited or signed for production; publicly visible source and APK artifacts.
- Future: proper normal typing keys, selectable Mandarin/English/Malay recognition, configurable tone and terminology, tests, stable release signing, move to a private dedicated repository.

## Technical notes
`VoiceKeyboardService` uses Android `InputMethodService`, `MediaRecorder` (manual start/stop), and `InputConnection.commitText`. API conversion uses OpenAI Responses via HTTPS, model `gpt-4.1-mini`, with short style/terminology guidance.

## Upgrade signing (important)
GitHub-hosted debug APKs commonly receive different signing certificates on different runners. If signatures differ, Android **cannot overwrite an existing APK**, even when the package name and version are correct. It is not possible to make v0.10 overwrite an already-installed v0.7 unless the original signing private key is available.

v0.10 CI now supports a persistent keystore stored as GitHub Actions **repository secrets**, without committing it to source control. The repository owner must securely generate one Android keystore and configure four GitHub Actions secrets: `AE_KEYSTORE_BASE64` (base64-encoded keystore bytes), `AE_STORE_PASSWORD`, `AE_KEY_ALIAS` and `AE_KEY_PASSWORD`. Once set, later builds signed using the **same** keystore may update each other in place. The first migration from the previous random debug signing identity may still require uninstalling the old APK and entering the API key again; safely back up the key before uninstalling. Do not paste or commit any keystore or signing password into an issue, chat, source repository, or public release. Until the four secrets are configured, builds remain ephemeral-debug-signed and cannot promise in-place upgrades.
